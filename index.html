How it works

A simple public promise

Use without friction

Most free tools and simulations open immediately. Some platform services use accounts only where identity, publishing, synchronization, or billing genuinely requires one.

Keep browser work local

Static tools are designed to process data on-device where practical. Optional AI or network features clearly depend on the browser, a user-provided key, or an external service.

Inspect and improve

Free-store projects follow an open-source, GitHub-based contribution model. Many experiences are intentionally self-contained so contributors can understand them quickly.

Pay only for server value

The intended Pro model funds capabilities that require persistent infrastructure: hosted AI, databases, storage, scheduled jobs, collaboration, and custom domains.

State maturity honestly

Live, beta, preview, and planned work are different. The public site and stakeholder brief identify those states instead of treating the whole ecosystem as equally complete.

Build a contributor path

The long-term goal is a community-maintained catalog where domain experts, educators, designers, and engineers can each improve a focused part.

What product status means

A public URL does not automatically mean a product is mature, supported, or ready for critical work.

Full status guide →

Production

The core workflow is deployed, tested, and actively operated. It can still change, and free services do not carry an uptime SLA.

Beta

The product works and is available for evaluation, but interfaces, reliability, catalog quality, and data handling may still change.

Preview or scaffold

Useful portions exist, but the end-to-end service is incomplete. A polished storefront is not evidence that every advertised workflow is operational.
